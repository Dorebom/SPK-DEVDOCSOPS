# EX-01 HEMS設計変更チケットの記入例

**これは架空の練習用記録であり、実製品への要求・設計承認・実行結果ではない。** 1秒制御要求を、観測可能な受入条件と計画へ落とす例を示す。実際の値は正本と機器制約を確認して決める。

## 1. 問題・目的

通常の機器ポーリングに高優先度の制御要求が混在すると、対象要求の送信が待たされる可能性がある。まず、対象機器・操作・計時区間・負荷条件を決め、優先度と送受信管理の設計候補を比較する。

対象は「送受信スケジューラの設計案とホスト上の検証計画」。製品への適用、電力会社出力制御の方式変更、実機への制御送信は本チケットでは認可されていない。

## 2. 基準とリスク

| 項目 | 記入例 |
| --- | --- |
| 要求 | EX-REQ-001：特定の制御要求を指定周期で扱う。対象・締切の定義は確認中 |
| 設計正本 | 実際の通信・優先度・タイムアウトの設計書を登録するまでUNKNOWN |
| 実装正本 | 実際のmodule/commitを探索し特定する。仮のファイル名を事実として使わない |
| R2の理由 | 共有送受信資源と高優先度制御の期限・競合設計に影響する可能性 |
| 認可 | 調査の認可を取得・参照した後にREADYへ更新。ここでは未認可 |

## 3. 受入条件の例

本件の受入は設計検討の受入であり、製品性能の受入ではない。

| AC-ID | 条件 | 確認方法 | 現時点の結果 |
| --- | --- | --- | --- |
| AC-01 | 「1秒」が周期、期限、応答完了時間のどれを指すか、対象操作とともに明記される | 要求と関係者判断の照合 | NOT_RUN |
| AC-02 | 高優先度と通常通信の負荷、キュー上限、滞留、飢餓防止を説明できる | 設計比較・反例レビュー | NOT_RUN |
| AC-03 | 再送・タイムアウト・通信断・再起動時の扱いが明記される | 状態遷移と異常系レビュー | NOT_RUN |
| AC-04 | ホスト検証と実機でしか確認できない性能・機器制約を区別する | 試験計画レビュー | NOT_RUN |

## 4. 影響分析の例

| 影響先 | 確認すること | 未確定事項 |
| --- | --- | --- |
| 共通送受信 | キュー、処理時間、帯域、キャンセル、期限超過の扱い | 現行の待ち構造・負荷上限 |
| 通常ポーリング | 低優先度側が無期限に待たされない条件 | 許容する鮮度・遅延 |
| 制御要求 | 受付・送信・応答のどの時点を測るか | 合意した時間要件 |
| 認証・暗号 | セッション準備や再認証の時間、非対応機器との分離 | 対応構成と処理時間 |
| 出力制御責務 | 選択されたPCS/GW方式と干渉しないか | 現行正本・対象機器 |

## 5. 計画の例

1. 正本とコードから現行経路を確認し、層とOSプロセスを区別した図を作る。
2. 対象操作・タイミング・機器負荷の要求を確定できる資料を作る。
3. 優先度付きキュー等の候補と、既存方式の拡張案を比較する。
4. ホストで再現する負荷・遅延・期限超過・飢餓条件を設計する。
5. 判断材料をそろえ、技術責任者へ設計採用の判断を依頼する。
