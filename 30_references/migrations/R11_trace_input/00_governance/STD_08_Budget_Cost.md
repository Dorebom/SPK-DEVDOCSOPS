# 予算・実績原価・発注残・完成時見込

## 1. 管理目的と境界
人件費、委託費、実機・部品、試験・認証、クラウド・AI利用、ライセンス、旅費等を対象にする。管理会計上の原価と現金支払を別にする。本STDは会計・税務処理の確定指示ではない。社内会計基準・購買契約を参照し、税・通貨・間接費配賦・内部工数単価は担当者が決める。

## 2. 予算基準
BUDに対象WBS/期間/リリース、通貨、税区分、費目、基準額、根拠、承認者・日時・証拠を記録する。予算案と承認予算を分ける。未決NULLは0でも無制限でもない。予備費と管理予備は、使用権限・残額を別表示する。未承認の増額を基準額に取り込まない。

## 3. 金額・工数の記録
金額は十進数文字列、通貨コード・税基準を必須にし、二進floatで原票額を丸めない。JPY例を全案件の通貨と断定しない。複数通貨の合算には換算日・採用レート・出典・丸め規則が必要。初期集計器は単一通貨・同一税基準のみ対応し、混在をエラーにする。
EFFは人が実際に作業した時間。AIの待機時間・実行時間を人の工数に重複加算しない。内部工数を金額へ換算する場合、工数表・単価版・適用期間から計上したCSTをリンクする。CSTを手入力した費用と二重加算しない。AIサブスク／API費用は別費目・配賦規則を持つ。

## 4. 発生と支払・発注残
| 記録 | 用途 | 集計 |
|---|---|---|
| 見積 | 将来の支出予想 | 実績ACに含めない |
| 発注総額・変更額 | 約束した支出 | COMとして管理 |
| 検収・発生原価 | 実績 | CSTとしてACへ加算 |
| 支払 | 現金の移動 | キャッシュ表。ACへ再加算しない |
| 未履行の発注残 | 将来に発生する拘束 | COM総額−対応する発生原価 |
原価認識済み・未払いを発注残へもう一度含めない。同じ請求をタスクごとに複製せず、原票から配賦し合計が原票額と一致することを確認する。今回の集計器はCST1行1taskの簡易配賦、同一原票キー重複を拒否する。分割配賦は原票行を明示分割し、運用レビューで総額照合する。

## 5. 予算監視の式
```text
BAC = 承認予算の対象総額
AC  = 締め時点までの発生原価
OC  = まだACに含まれていない発注残
ETC = 現時点から完了までの将来原価（OCを含む）
EAC = AC + ETC
VAC = BAC - EAC
```
ETCにはOCを含むため、EAC=AC+OC+ETCと二重加算しない。OCがETCを上回る場合は、解約・減額の承認根拠又は見積修正を要求する。機能別残工数を金額にする場合は将来単価を明示する。残予算は残作業コストと同じではない。BAC又はETCが未確定ならVAC/EACを未算出とする。
EV/PV/CPI/SPIを採用する場合は、費用ウェイト付き出来高・時系列予算配賦・基準版が別途必要。工数ウェイトの進捗をEV金額と呼ばない。初期集計器はEVMを実装しない。

## 6. 訂正・監査
確定原価は直接削除せず、取消又は調整行にreverses_id・理由・証拠を持たせる。未計上→計上→確認の履歴を原票と関連付ける。支払記録で負の工数を相殺しない。月次締め後修正は次期訂正として承認する。購買上限・予算超過閾値・承認分掌はOpen Questionで確定する。

## 7. 未整備の明示
今回の配布物に実際の予算・単価・請求・労働時間は入力していない。空台帳は0円実績を意味しない。actuals_complete_throughを確認者が設定するまで集計はPARTIAL/NOT_CONFIRMEDと表示する。テスト用金額は合成試験だけに置き、実運営レポートへ含めない。

## 7. R11：多Trace・多工程の会議／調査と費用
同じ会議の参加工数、同じ調査費、同じ共通成果の費用を、関連Trace数やphase_ids数だけ複製しない。原票はEFF/CST/COMとleaf TASKに一度だけ記録する。配賦が必要なら原票ID＋配賦先Trace/phase＋比率＋根拠を別表で管理し、同一原票の合計比率=1を確認する。配賦未定と費用0を混同しない。本版tracecheckは費用配賦計算をしない。

## Open Questions

担当・実予算・承認閾値・運用環境の未決は [GOV Open Questions](Open_Questions.md) を参照する。本文の運用案は、未確定の製品仕様や支出の承認を代行しない。
