# CTX-R11 — TraceIDの開発ライフサイクル全体への適用

記録日：2026-10-08。ユーザーは、TraceIDを以下の17工程と関連した調査・会議の関係が途切れないように管理する目的で使いたいと明示した。工程名・主な内容はユーザー提示を保持する。

| # | 開発フェーズ | 主な内容 |
|---|---|---|
| 1 | **企画・構想** | 課題定義、目的、対象ユーザー、事業要求、開発範囲 |
| 2 | **要求分析** | ユーザー要求、ステークホルダー要求、ユースケース、制約整理 |
| 3 | **要求仕様策定** | 機能要求、非機能要求、外部仕様、受入条件 |
| 4 | **システム設計** | システム構成、責務分割、HW/SW分割、インターフェース |
| 5 | **アーキテクチャ設計** | プロセス構成、レイヤ構成、データフロー、通信方式、状態管理 |
| 6 | **基本／構造設計** | モジュール構成、コンポーネント、API、状態遷移、DB／データモデル |
| 7 | **詳細設計** | クラス、関数、アルゴリズム、通信シーケンス、例外処理 |
| 8 | **実装** | コーディング、静的解析、コードレビュー |
| 9 | **単体テスト** | 関数・クラス・モジュール単位の検証 |
| 10 | **結合テスト** | モジュール間、プロセス間、通信インターフェースの検証 |
| 11 | **システム／機能テスト** | システム全体として要求仕様を満たすか確認 |
| 12 | **非機能テスト** | 性能、負荷、耐久性、セキュリティ、障害耐性 |
| 13 | **受入・妥当性確認** | ユーザー要求・製品要求に対するValidation |
| 14 | **リリース準備** | リリース判定、成果物整理、マニュアル、移行計画 |
| 15 | **リリース／導入** | 製品・サービスへの展開、現場導入 |
| 16 | **運用・保守** | 障害対応、監視、改善、アップデート |
| 17 | **振り返り・改善** | 開発プロセス、品質、設計、組織運営の改善 |

## 今回の具体化案との境界

P01〜P17というコード、版付きノード・型付き関係、工程別の記録確認、書式・検査器は今回の具体化案。担当・採用機能・権限・数値・試験結果・予算の新たな承認ではない。既存製品仕様のBL-R9-0001は更新しない。
