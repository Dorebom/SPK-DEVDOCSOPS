# R8 仕様完成・編集ガイド

## 1. 正本と生成物

`00_MOC.md` が単一の入口。`chapters/I_System`〜`V_Lifecycle`の本文と章末Open Questionsを編集する。規範別冊は各詳細表を所有する。`90_All_In_One.md` とOpen Question横断台帳は生成ビューで、直接編集しない。質問回答は章末を正本とし、JSONへ別に二重入力しない。機能一覧は `data/function_catalog.json`、SYS要求本文は `data/requirements.json` を編集し、対応ビューを再生成する。権限・構成の詳細は規範別冊を正本とし、R7由来JSONは継承時点のスナップショットと区別する。詳細は `data/canonical_ownership.json` を参照。

旧R7は入力スナップショットとして `sources/r7_snapshot` に隔離する。旧27章への薄い案内だけを新仕様と呼ばない。章をまたいだ引用・参照はIDと旧新対応表で追う。

## 2. 機能一覧の完成

I-03の21全体機能群とII-02の32GW機能群は一覧化済み。採否、対象リリース、既存全機能調査、USDM、具体的条件は未決である。機能群IDを、承認済みの原子的な要求IDと同一視しない。1つの全体機能が複数GW機能やPCS・クラウドへ配賦される。

## 3. ロール別機能の完成

人の利用者はユーザ／メンテナンス／メーカー／開発者の4分類。名称は確定、具体権限は未承認。I-02に役割・機能群概要を残し、詳細な操作・対象・環境・期限はRole_Function_Access別冊で決める。UIで非表示にするだけで認可を済ませない。通常APIから系統制約を迂回しない原則を維持する。

## 4. 構成パターンの完成

I-05にCFG-RS／CFG-EL／CFG-MIXの代表を記載する。取得主体・故障影響が変わるものは本編、型式・版・台数・配線等は構成・機器別冊へ置く。設置記録は適用プロファイル版と実個体を結ぶ。任意の組合せ対応、PCSなし構成、自動取得主体切替は今回追加しない。

## 5. OQの回答

質問の記入正本は担当章末尾1か所。既存OQ/SLOT IDは旧章数字を含むが改番しない。回答、根拠資料ID・版、対象構成、承認者、決定記録、状態を更新し、解決した値・条件を本文又は規範別冊へ反映する。4分類名称のような部分回答は、未解決の権限質問を閉じずに記録する。

G0〜G4は既存管理案であり承認済み日程ではない。未割当の担当者・未定の期限を勝手に補完しない。試験未実施と受入条件未確定を区別する。

## 6. 再生成・検査

Python 3.11以降を想定。標準ライブラリのみを使用する。

```text
python tools/sync_views.py
python tools/validate_r8.py
# 配布時の継承不変性も確認する場合
python tools/validate_r8.py --baseline-check
```

自動同期対象は統合版、OQ横断台帳・状態索引、機能一覧・カード、SYS要求カタログである。他の台帳・詳細契約の整合は個別に更新・レビューする。再生成は本文の役割や数値を自動決定しない。入力が不正な場合は処理を中止してエラーを表示する。リンク・ID検査は技術適合や意味的な完全性を証明しない。
