## 1.1 配布ZIP補修：R8-FIX001（2026-10-08）

修復後はR7非ZIP原本175件の一致、現行アーキテクチャ原典19件の一致、現行仕様構造と124要件・69試験・85 OQの維持を確認する。旧版ZIP6件の再帰的同梱は復活させない。配布物本体に対しZIP CRC・Manifest SHA-256・保存宣言を再検証する。詳細は [補修ログ](REPAIR_LOG_FIX001.txt) を参照。

**本文・機能・要件の技術的変更はない。** 文書QAのPASSは実機・認証の確認を意味しない。

## 2. 範囲・限界

この版は、ユーザー指定の5部を実際の本文分類へ反映する再編である。権限・機能採否・機種対応・数値・正式USDMの未確定事項は解決していない。章を移したこと、リンクが存在すること、元データと一致することを、仕様の意味的な完全性や製品の受入完了と読み替えない。

外部の規格・JET・一般送配電事業者・ECHONET Liteの資料を今回再取得・再検証していない。資料に由来する説明は継承時の確認範囲である。実機／POC／負荷／故障注入／脆弱性試験／認証判断は未実施で、既存69試験はNOT_RUN。

sources配下は変更しない保存領域。そこにある旧版のリンクは歴史的状態であり、除外した旧ZIPへの参照を現行の依存にしない。検査は保存ハッシュを確認し、歴史的なリンクや旧章番号を修復していない。

ZIPのCRC、安全な相対パス、含有ファイルは配布前に検査する。配布時のSHA-256はZIPの隣の .sha256 ファイルに記載する。個々の同梱ファイルはMANIFEST_SHA256.txtで確認する。

## 3. 再実行

```text
python tools/sync_views.py
python tools/validate_r8.py --baseline-check
```

仕様内容を正式に改訂した後は、意図した差分まで「不変」とは判定しない。通常の構造検査は--baseline-checkを付けずに実行し、変更根拠を別途残す。
