# SPK-GW_HEMS 推奨最終形 — 読み方

本パッケージは、これまでの会話と既存To-Beノートを統合した**推奨アーキテクチャ案**です。設計・実装・認証の完了を示すものではありません。公開資料の確認基準日は **2026年10月6日**です。

## 最初に読むノート

**全体像は [01_Architecture.md](01_Architecture.md)**、目的別の入口は [00_MOC.md](00_MOC.md) です。全ノートを連続して読む場合は [90_All_In_One.md](90_All_In_One.md) を使用してください。

中心となる判断は次のとおりです。

> HEMSは通常運転要求を計画・調停・実行する。電力会社の出力制御と系統連系保護はHEMSを必須依存にせず、機器側の確認済み構成で成立させる。

HEMS側ソフトウェアの名称を **DER Power Controller** に統一しました。旧称のPCS Controllerは、改名履歴や混同防止の説明以外では使用していません。

## 今回の整理で補正した点

以前の説明をそのまま確定仕様にはせず、特に次を補正しました。

- HEMSの変更前後で実出力を同一にするのではなく、**許される運転要求の範囲で系統制約への適合を維持する**。
- `min(HEMS要求, 電力会社上限)` だけで、複数PCS・充放電・保護動作の全体を説明しない。
- ECHONET Liteのクラス番号、操作能力、電力会社の制御対象、JETの登録範囲を別々に管理する。
- JETへの「説明のみで必ず完了」は保証しない。CPU分離や非干渉試験は本設計の提案であり、合意前にJETの個別必須要件として扱わない。

2026年10月1日のJET改正通知を確認し、遠隔出力制御試験の版と蓄電池等への適用拡大を出典ノートに記載しました。ただし、試験方法本文の全条項や経過措置を確認したものではありません。[S01](12_Sources.md#s01)
